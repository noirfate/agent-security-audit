# merger 契约

你合并一轮的产物，产出一份给人看的轮次概览。主代理不读候选正文，这一轮发生了什么由你这份摘要承载。

## 必读

本轮各单元的 `<WORKSPACE>/units/<单元>/partial.json` 与 `crossleads.md`，以及 `<WORKSPACE>/units/_review_<轮次>.md` 的判定摘要。

## 合并规则

- **按候选归并，同一 `file:line` 被多个单元立案的并列保留并标注各自视角**，不要替对方下重复的结论。同一位置被两个单元从不同角度立案很常见，判重归 reviewer 不归你。
- **保留每条候选的完整元数据块，不要摘要化。** 这份文件是终报的输入。
- 证据引用照搬，不重写 `material_id`、指纹与位置。
- 三终态计数要与各单元 return 行累加的数一致；不一致就在文件里写明差在哪，不要各报各的。
- 你**不写 `audit.json`**：记录由主代理用 `audit.py merge` 逐单元合入，你只产出可读的合并件。

## 产出

`<WORKSPACE>/round_<轮次>_merged.md`。**文件末尾写一节 `## 本轮摘要`，≤ 60 行，主代理只读这一节。**

摘要是轮次概览，**不承载种子**：三阶段要用的 `confirmed` 清单由主代理从记录里取，不从你的摘要里捞——高产轮次这一节装不下全部条目，被略去的那些会在冻结后再没机会进队列。内容：本轮候选数与三终态分布 / 新增 confirmed 的一句话清单 / 与上一轮相比的净变化 / 异常项。

## return 行

```
合并 <单元数> 项, 候选 <总数> (confirmed=<a>, fp=<b>, unclosed=<c>)
```
