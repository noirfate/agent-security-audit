# 分析方法

本指南描述如何取得目标证据。风险、命题、对象边界与控制内容均查询随包框架，不在方法文档中复制目录。

对象查询附带专项方法索引。只读取当前检查相关的`procedure`，其元数据和正文位于`references/procedures/`；候选方法不改变对象定义或命题适用性。审计执行不会新增或维护这份通用方法目录。

## 事实、假设与安全要求

从文档确定设计意图，再用实现核对。记录实际输入及其提供者、身份与角色、受保护资产、敏感操作和安全要求。安全要求须有目标语义或框架技术依据，例如“只有数据属主可以读取”“批准绑定最终动作”“删除后的状态不可通过旧检查点回流”。假设单独登记，不能把组件名称、宣传或注释当保证。

能力选择依据真实依赖、调用、结构字段和部署制品。关键词用于找位置；既不能用词频点亮能力，也不能由搜索零命中排除能力。检查自有封装、生成输入、配置和同名异义。无历史案例仍要从职责和安全要求分析。

资产不限于数据与密钥，也包括授权状态、任务意图、记忆完整性、批准票据、共享资源及可恢复性。攻击者可以是低权限用户、第三方工具、被读取内容的发布者或受委派Agent；系统作为客户端接收的外部响应也是输入。

## 攻击入口类型

攻击入口类型描述攻击起点相对于被审目标运行环境的位置。审计开始时明确目标的内部运行环境边界，后续分类保持一致。权限高低、利用条件、严重度和证据完整性分别记录，不作为入口类型的替代判据。

| 类型 | 环境 | 定义 |
|---|---|---|
| `EXT` | 外部环境 | 攻击起点位于用户无法直接控制的外部不可信环境，攻击内容通过目标接收的请求、内容或服务响应进入。不要求预先进入目标内部环境，也不依赖特定的邻接位置。 |
| `ADJ` | 邻接环境 | 攻击起点位于目标内部环境之外，但与内部环境存在受限的网络或运行环境邻接关系。攻击必须依赖这种邻接位置才能接触相关入口。 |
| `INT` | 内部环境 | 攻击起点已经位于目标所属的内部运行环境，即用户用于运行和管理该目标的环境。攻击者从该环境中的账号、进程、文件或组件发起攻击；其已有权限和控制范围单独说明。 |

1. **按攻击路径的起点分类。** 外部内容经过下载、存储、解析或执行后，不因此改变整条链的入口类型。
2. **用户操作不改变环境归属。** 配置外部服务、打开内容或触发处理属于利用条件，不自动将 EXT 转为 ADJ 或 INT。
3. **内部不等于可信，外部不等于匿名。** 内部可以存在低权限恶意主体；外部攻击也可以要求身份认证。
4. **ADJ 必须有明确的位置依据。** 记录具体邻接关系，以及为何攻击依赖该位置，不能把 ADJ 当作模糊的中间档。
5. **分类与缺证分开。** 起点环境无法确定时记录“未确定”及具体缺口；起点已知但后续链路缺证时，保留入口类型并记录缺口。`unknown` 只表示尚未完成分类，不是第四种入口类型，也不代表已裁决。
6. **不同路径分别判定。** 同一漏洞可存在不同环境的入口，分别说明路径及前提，不直接继承组件或审计单元的标签。

## 六种分析方法

### 双向追踪

先从具体输入字段顺着代码或文档流程追踪，记录数据变换、身份转交、授权、状态写入与最终副作用；再从敏感操作反查调用者，验证攻击者能否控制所需字段。正向分析不限于已知危险函数，反向检索要覆盖项目封装与别名。

长链按节点记录“位置、输入状态、主体、已验证控制、输出状态、下一跳”。遇到动态分派或缺失依赖，保留未解节点与证据缺口；只把连续可验证的路径作为成立依据，不跨过空白环节。需要运行行为才能确定时，停留在静态可证范围。

### 防护有效性

逐项核对四个问题：

1. **缺失**：由目标要求推导需要的控制，再看相关路径是否实现；没有同名函数不证明没有控制。
2. **覆盖**：同类入口、批量路径、恢复、重试和回退是否都经过控制；上游控制要核对全部相关到达路径。
3. **正确性**：检查控制实际比较的主体、资源、参数、有效期与返回值，关注异常、空值和失败时的行为。
4. **绕过**：静态检查编码转换、重定向、别名、状态改变及检查与使用之间的变化是否使约束失效。

控制记录写明保证、条件、责任方与未覆盖范围。模型安全策略、扫描通过或容器存在不能替代具体保证。判为不成立需要能否定目标失效机制的反证；资料不足保留缺口。知识库条件与取证清单仅供参考，具体检查方式和证据充分性由模型判断。

### 信任模型与平台承诺

对每条边界记录谁提供什么、消费者信任什么、实际权限和授权来源。特别核对自然语言内容是否改变授权决策、下游是否误把代理身份当用户权限、调用方声明是否被当认证结果。

比较目标需要的隔离单位与平台提供的保证。例如宿主或工作负载级隔离不自动证明任务与租户隔离。读取部署配置、共享通道、挂载和凭据注入，分别记录平台承诺、目标启用情况及可见证据。缺部署材料时保留责任与可见性缺口，不默认平台兜底。

### 同类操作横向核查

从一个实例扩展到同类敏感操作、同一控制的调用者及旁路。将查过的范围与遗漏路径写入覆盖记录，按共同根因归并发现。检索失败不算零命中，输出截断不算完整枚举。

### 能力组合

从实际可用能力检查组合路径：读取是否能接到外发、状态写入是否能接到后续指令解释、委派是否能扩大身份范围。每段记录前提及控制，只有兼容的主体、状态与运行场景才能拼链；两个独立候选不会自动构成攻击链。

模型先依据实际证据识别攻击原语，再按单元记录；矩阵供模型判断哪些能力可能组合，脚本不自动建立攻击链任务。原语是攻击者通过缺陷获得的最小原子能力，与界面模式族互补：模式族自底向上找代码形态，原语自顶向下问「这个单元能提供什么能力」，后者能发现不匹配任何已知模式的能力来源。

| 代号 | 含义 | 在 Agent 里的典型来源 |
|---|---|---|
| `INJECT` | 把一段文本提升为对模型有效的指令 | 外部内容摄入、工具描述与 schema、工具返回、同伴 Agent 消息、Skill 正文与规则文件 |
| `PERSIST` | 让一次注入跨会话存活 | 长期记忆写入、检索索引写入、检查点与缓存、配置自改写 |
| `EXFIL` | 把数据送出信任域 | 渲染触发的资源加载、出站请求、工具副作用、日志与遥测 |
| `EXEC` | 以 Agent 的身份执行代码或命令 | 代码与脚本执行器、模板渲染、沙箱不安全回退 |
| `READ` | 读到攻击者本无权访问的数据 | 路径穿越、服务端请求伪造、记忆跨主体读、检索越界 |
| `IMPERSONATE` | 改变最终生效的主体 | 委派与子 Agent、服务账户、令牌转交、声明式身份 |
| `APPROVE_BYPASS` | 跳过或伪造人机审批 | 自动批准开关、检查与使用之间的变化、终端界面欺骗、策略自改写 |
| `ESCAPE` / `DOWNGRADE` | 突破隔离单位 / 削弱已有控制 | 容器与工作区、租户与会话命名空间；关闭护栏、跳过校验、降级协议 |

每条原语记在目标记录的 `primitives` 里，带单元、证据与来源（由模型核实后登记，原始命中不自动变成原语）。两个用途：

- **优先级**：同时提供三类以上原语的单元优先排轮次，攻击者在一个单元内就能组合出链。
- **链候选**：`INJECT` + `READ` + `EXFIL` 同时可达即致命三要素闭合；`INJECT` + `PERSIST` 是跨会话持续；`APPROVE_BYPASS` + `EXEC` 是审批面失守。按这些组合立三阶段的链单元，再逐段验证主体、状态与可达性是否兼容。

矩阵只给候选。一个单元「能提供」某原语是待验证的判断，不是已成立的发现；拼链仍要求每段有已成立的检查支撑，中间不留空白环节。

### 资产目标反查

为实际攻击者选取具体资产目标，反查能否通过任何已知入口达成。分析来自目标要求，不以风险目录是否已有名称为边界。无法关联框架的可证机制建立本地检查；只有假设时登记假设与所缺证据。

## 检索与覆盖

枚举文件与构建单元后明确范围；按语义处理源码、协议定义、模板、配置、提示词与文档，不按扩展名粗暴排除。隐藏目录与忽略规则可能包含重要配置，明确记录实际检索范围。审计工作区、知识快照及报告不得作为目标实现存在的证据。

优先使用`rg`。退出码1表示搜索没有匹配，2或其它错误表示搜索未完成；任何“没有”结论先确认路径、过滤和命令有效。引用保留文件内容指纹与位置，不能只保留易漂移的行号。

覆盖记录描述完成了什么分析，不能把文件枚举数或关键词命中数当漏洞覆盖率。尚未检查、检查后证据不足和明确范围外分别表达。复杂组件仍需分析实际入口与控制，不能因复杂而自动排除。

## 发现复核

发现复核单独落成记录，明确是谁复核、回读了哪些材料、找到了什么反证、为何保留或撤销，以及缺少哪些证据。仅改写初审报告不算回源复核。撤销项保留在目标知识库中，避免下一轮将同一疑点再次当新发现。

从被阻断的失效路径提炼控制有效性，关联具体检查和反证。说明保证适用于哪个入口、主体、配置和版本，以及如何回归验证。控制存在、样本拒答和某风险不适用，分别不足以单独证明控制有效。

说明机制、前提、实际权限、受影响资产和具体控制缺口。确认来源到操作可达，检查中间件、接口实现、宿主加载行为、默认配置与回退路径的反证。区分预期功能和超出授权的使用；严重度由目标场景决定，不继承目录标签。

设计缺陷可以用“安全要求—假设—实际能力—违反点—后果”论证，不强制拼成代码数据流。LLM行为依赖实验的部分不能仅凭可疑指令确认成功率；静态可证缺陷与模型行为假设分别记录。

## 发现、同源与风险类别

finding 是审计观察；事实复核保留后，还要比较其与其他发现的关系。一个具体缺陷可以被多个检查、入口或发行副本观察；相同命题、文件、函数、CWE、安全要求或修复提交都不是同源的充分条件。

归并须回源说明相同失效机制及共享控制实现或可证的同源实现，逐成员保留前提、路径、影响和反证。独立实现违反同一抽象要求时分别保留，可以归入同一阅读主题。部分重叠交回拆分，组合链和汇总不另增漏洞数；链中新识别的具体缺陷仍正常登记、复核和归因。
