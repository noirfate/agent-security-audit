# 按目标组织审计

目标类型可以叠加；下面的对象编号用于首次查询，不构成封闭清单。按实际职责扩展到接口、记忆、观测、基础设施和跨域对象。模块选择要有材料依据。

专项方法由`knowledge.py procedures <对象id>`列出，`procedure <方法id>`读取。Skill优先查看`skill-integrity`，MCP查看`mcp-boundaries`；框架和业务系统按职责查看`instruction-trust`、`action-authorization`、`state-isolation`、`runtime-isolation`、`interface-rendering`、`control-evaluation`。索引是取证导航，不是新的对象—风险映射。

## Skill制品及宿主集成

先区分“只审制品”和“包含宿主加载路径”。查询A2.5的定义与命题，再按实际成员识别工具目录、执行器和供应链对象。

- 清点正文、引用文档、脚本、依赖、初始化与更新配置；保留外部引用的版本和可变性。
- 对照声明用途，分析隐含前置步骤、异常路径、超任务行为要求、秘密处理及来源伪装。不要执行Skill来观察行为。
- 若宿主可见，追踪加载后消息角色、实际凭据、工作区、网络、批准与撤销机制；声明权限和有效权限分开核对。
- 包外内容未取得或宿主不可见时，明确哪些制品行为已读到、哪些加载/执行效果尚未证实。不能仅凭“含Shell脚本”或“要求某工具”确认宿主逃逸。

审计Skill时Markdown正文必须进入材料与检索范围；安装的本审计工具及其目标知识库按实际路径排除。

## 成堆的制品

模型按制品职责、共享依赖、调用关系和可处理上下文划分单元。存在明确重复问题时可用内容指纹与 diff 辅助比较；代表性、相同部分能否复用及差异的影响由模型判断，复用须写明依据与局限。

`triage` / `standard` / `deep` 记录模型选择的分析深度及理由。制品数量、关键词命中和目录形状是定位信息，不决定分片、代表或深度；每个范围内材料仍须有分析记录或明确的跳过理由。

有些性质单审任何一个制品都看不见，必须在跨制品单元里查：

- 两个制品声明同名工具时宿主按什么顺序解析，用户看到的是哪一个。
- 能力聚合：A 包只能读私有数据、B 包只能外发，装在同一宿主就凑齐了致命三要素，而单审两个包都是「无发现」。
- 多个制品读同一环境变量或同一令牌时，实际权限是并集，不是单个制品声明的子集。
- 同一模板或同一上游的缺陷命中整簇，定级按簇而不是按单个制品。
- 共享依赖与锁文件横跨多个制品。
- 制品总数下宿主的允许清单与逐次确认是否还能被人实际执行——审批疲劳就是人机审批的事实失效。
- A 的输出进 B 的输入时，工具返回注入跨制品传播。
- 同一制品被多个 Agent 复用时的身份混用。

## MCP客户端、服务端与代理

查询A4.3及实际涉及的工具目录、调用器和连接器对象。先确认具体角色、传输方式、所用协议版本、远程或本地部署，避免把一个角色的要求摊到另一个角色上。

- 从连接建立到能力发现，再到实际调用与结果回填，逐段核对主体、受众、资源与任务范围。
- 将tools、resources、prompts及返回内容按实际消费方式归类，分别检查来源、变更、指令地位和授权。
- 认证中间件、令牌转交和下游连接身份需要追到实际实现；不能由“支持OAuth”推断委派正确。
- 检查协议面与管理面，以及服务动态变化与已审内容的绑定。对stdio服务不强套公网入口假设。

静态审计不启动服务、不连接端点、不发请求。已有客户端配置和日志可以作为静态材料。MCP专项来源条款经角色和版本筛选后使用。动态补证遵循独立流程；内置HTTP工具不是MCP协议客户端，真实MCP会话由已有授权测试工具采集后导入，不能伪装成普通JSON对话。

## Agent框架

先理解框架提供的扩展点、默认运行方式及部署者负责的配置，区分库能力、示例应用与用户自行编写的实现。

- 沿消息组装、计划调度、工具分派、结果回填、记忆更新和恢复路径建立实例与连接。
- 核对默认策略、扩展接口和错误回退是否允许越过已有控制；调用方可配置的危险行为要说明所需前提。
- 对可插拔身份、存储和沙箱，分析接口契约与默认实现分别保证什么。只有接口没有实现时保留缺口。
- 追踪多Agent委派、状态共享、取消与预算传播。类型声明、元数据和能力描述不能自动当作实际授权。

框架设计为执行用户代码并不自动构成代码执行漏洞。需确定越过的任务、主体、资源或隔离边界。

## Agent业务系统

从实际业务目的、角色和受保护资源出发。查询相关对象后，将其映射到真实业务接口、数据访问和工具动作。

- 建立用户/Agent/服务账户的代表关系与资源归属，检查资源读取、写入和副作用最终使用的身份。
- 对自然语言查询、交易、发布或删除等操作，检查参数、资源范围、批准绑定、幂等与回滚要求。
- 既审模型引导与工具链，也审普通API、会话、渲染与管理路径；Agent没有参与的旁路仍可能影响同一资产。
- 将平台能力、部署配置和业务责任对照，沿真实链路检查多租户隔离、数据发送、状态恢复与供应链变更。

对云服务的说明仅作为责任边界和可见证据；不从厂商名称或“托管”标签推导安全结论。
