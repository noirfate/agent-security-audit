# 动作授权、审批与委派

取得入口身份、资源归属、调用器、审批票据、委派消息、重试与回退逻辑。先写目标安全要求，例如调用者只能修改自己租户的记录；不要把「有管理员功能」作为漏洞。

正向跟踪攻击者参数，反向从最终副作用追到调用身份。记录最终采用的是用户、Agent、代理还是共享服务账户。审批检查绑定的对象应包含最终动作、资源、参数、接收方、有效期和单次使用条件，按目标语义判断必需项。

比较检查前后的参数变换与重定向；横查批量操作、恢复、重试、异步队列、工具直调和多 Agent 委派。组合链必须保持兼容的主体、状态与权限，不把不同会话的片段拼成一次攻击。

反证重点：上游中间件对全部入口的覆盖、策略拒绝在执行点是否生效、审批之后参数是否冻结、撤销是否传播、下游是否再次授权。前端按钮和自然语言确认不能代替未证明的执行控制。

一般命令执行能力、用户主动选择的 URL 或文件路径不自动构成漏洞。证明另一主体如何借助高权限执行者超出批准范围；同样不能因接口是本地 CLI 就忽略第三方内容输入。

对动态动作验证使用受控记录、临时资源及副作用观测；自然语言「已付款/已删除」不是执行证据。静态范围只报告代码可达性和控制缺口。
