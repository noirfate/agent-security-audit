# MCP 身份、元数据与调用边界

先确定宿主、客户端、代理和服务端角色，以及实际协议版本、传输和部署形式。读取连接配置、认证中间件、工具注册、资源读取、prompt 定义、返回内容及下游连接器。

分别追踪发现、调用、结果回填三条路径。记录令牌由谁签发、受众和资源范围、最终下游身份；核对主体不能仅靠对话或工具参数自报。比较发现时元数据与调用时实现的版本、名称和绑定关系。

名称混淆（Name Confusion）与同名覆盖：沿注册、聚合、展示、选择和调用解析核对工具名称、标识、提供方与实现。关注命名空间丢失、来源由条目自述、别名或规范化碰撞，以及注册顺序或刷新改变绑定的路径。名称相似或存在同名工具本身不足以成立；结合目标判断是否造成身份误认、信任错用或调用偏转。目录身份问题参考FM-A4.1-05，最终分派与批准绑定参考FM-A4.2-01。

Rug Pull：核对首次批准后定义、响应或行为的变化能否沿用原信任，包括重连、能力刷新、远端更新或按时间、调用次数、输入触发的切换。服务名、本地包和版本号不变不等于运行内容不变；不能以观察到一次正常响应证明后续稳定。参考FM-A4.3-02及FM-X3.5-01，依据代码、配置或已有记录判断；缺少远端实现时保留相应缺口。

Tool Shadowing：除同名注册遮蔽外，还检查一个工具的描述或定义能否通过共享上下文改变其他服务工具的选择、参数或动作。这条指令影响路径不要求名称冲突，也不要求被投毒工具本身被调用；参考FM-A4.1-01及指令解释边界。MCP09的未受管服务属于另一种机制。

取证跟随实际机制：指令注入引用模型实际可见的指令文本及消费路径；名称或身份混淆核对发现条目、来源与解析绑定；实现投毒或行为变化追踪代码、状态及实际内容。各类证据不要求同时具备。工具输出注入检查外部来源、输出角色、宿主上下文组装和后续敏感能力，不能用「原样返回网页」直接证明越权已发生。这些方向均为参考，由模型结合FM命题和目标决定检查方法。

反证重点：上游认证覆盖的所有路由、每资源授权、凭据受众检查、元数据及行为变更的重新信任、宿主动作策略。分隔符、净化函数或 OAuth 名称本身不是充分保证；读其实际比较和执行位置。

stdio 工具不自动具有公网风险，合法文件/HTTP 工具也不自动存在任意文件读取或 SSRF。把调用者授权、服务账户权限与攻击者可控输入分开。

记录每一跳的角色、主体、资源和证据。缺服务端、宿主或线上配置时保留对应缺口；需要真实调用验证的部分转入单独授权的动态流程。
