# Skill 声明、加载与制品完整性

用于 Skill 制品及可见宿主加载路径。对象定义与命题查询固定框架；前提、判据和以下取证方法均供模型结合目标参考，不新增风险映射。

先取 SKILL.md、引用文件、入口、依赖和加载配置。材料清单保留缓存、构建目录、隐藏文件和字节码；二进制无法阅读时记录加载者、来源、摘要及分析缺口，不能执行它来补齐证据。

沿「声明的任务 → 指令要求 → 参数来源 → 实际脚本/能力 → 接收方或状态修改」核对。安装、更新、失败回退和可选 helper 均检查是否实际激活。编码文本保留原文和候选解码视图；只有加载或解释路径成立时才判断其作用。

成立证据须说明独立攻击者控制了什么、用户允许了什么、哪个生效指令或路径扩大了范围。只审制品时可以确认其中存在恶意要求，但不能声称宿主已执行或已逃逸。

反证重点：宿主的真实权限、只读默认、参数白名单、任务绑定、入口前置批准、引用版本与真实性检查。文档中的确认要求和代码中的强制确认分别记录；解释执行的纯文档 Skill 则检查宿主是否落实约束。

常见误报：正常认证被当外传，备份被当窃密，定时任务被当后门，Base64 或陌生域名被当恶意证据。按目标用途与接收方判断；多个弱线索不能靠数量形成攻击链。

将取证路径与反证写入目标检查；不可见远程载荷、字节码行为和宿主效果写入 missing_evidence。复核保留严重度与恶意意图两个独立判断，不根据高危等级推断作者意图。
