# 指令与外部内容的信任传递

读取消息组装器、system/developer 模板、Skill 加载器、检索结果拼装、工具输出和历史恢复路径。从实际入口确定谁能发布内容、谁会读到它，以及内容获得的消息角色。

追踪「外部内容 → 转换/摘要 → 上下文位置 → 决策或工具参数 → 执行控制」。摘要、跨 Agent 转发和记忆写入可能改变来源标记，需要逐段检查，不能只检查第一次输入。

成立证据应指向明确的信任提升或权限失效。攻击文本本身、模型看到不可信数据、两个工具同时存在，都不足以证明攻击成功。模型是否服从载荷属于行为假设，静态报告保留这一限制。

反证重点：来源标记是否持续、消息角色是否固定、数据是否能改策略、工具执行是否仍受独立授权与参数校验约束。模型拒答策略、分隔标签和转义各自证明的范围不同。

区分指令式任务说明、被引用的攻击样例与生效攻击指令；正常「必须执行此步骤」不能仅凭措辞判为注入。真实危险行为也不能因作者将其称为诊断而豁免。

把未闭合的中间节点保留为假设或证据缺口。动态补证需把载荷放到真实外部载体；在用户 prompt 中模拟一段工具返回，不能等同实际工具输出通道被突破。
